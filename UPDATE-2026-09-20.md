## 1. Excursion no longer scans back before the fill

**Found by:** 2026-09-18, the first VPS session. SNXX reported
`MAE -26.89 (-3.86%)` and MARA `-2.63%` — both far beyond the −1.50% bracket
stop, on a day where no stop was hit and all three trades were winners.

**Cause:** `_refine_excursion_from_bars` used

```python
since = self._bar_scan_from.get(symbol) or (now - timedelta(minutes=20))
```

on first sight of a position. SNXX filled at 10:00:45, so the very first
sweep pulled minute bars from **09:40** and scored the opening range as that
position's own adverse excursion. Every trade in the trial has this — the MAE
column in `state/trade_features.csv` is contaminated for any trade entered
within 20 minutes of a volatile stretch, which for an ORB bot is all of them.

**Why it is not merely cosmetic:** `_check_trailing` arms off `mfe_pct`.
Shorts are off today, but with `allow_shorts` on, a pre-entry *high* would
inflate MFE and could arm the trail off a price the position never
experienced — the 2026-09-09 IRD failure mode, reintroduced through the back
door. And MAE is precisely the statistic someone would later cite to argue
for a wider stop. A number that is wrong in the loss-making direction is the
dangerous kind.

**Fix:** the scan window is clamped to the fill time, taken from
`state.entry_times` (falling back to `_first_seen`, when this runner first
observed the position, for an overnight leftover with no row). The bar that
straddles the fill is dropped as well, since its high/low span prices from
before entry; the 30-second unrealized poll already covers that first partial
minute.

**Regression test:** `test_excursion_never_scans_before_the_fill` reproduces
the SNXX shape exactly — a −3.83% pre-entry dip must not appear, a +1.73%
post-entry high must, and the requested fetch window must start at the fill.

**Note when reading old numbers:** historical MAE figures predating this
commit overstate adverse excursion. Do not compare them against post-v1.17
trades, and do not use them as evidence for a stop change.

## 2. Graceful shutdown — `systemctl stop` now flattens

`run.py` installs a SIGTERM/SIGINT handler that calls `Runner.request_stop()`.
The handler only sets a flag; all broker work stays on the main loop, so a
signal can never land mid-order-submission. The loop checks the flag, runs
`_flatten_all_verified()`, and falls through to the normal `_final_report`, so
a stopped session still writes its EOD summary and trade history.

- `_sleep()` replaces `time.sleep()` in the loop and the pre-open waits, so a
  stop is honoured within a second instead of up to 300.
- A **second** signal exits immediately and logs loudly — for when the flatten
  itself is stuck.
- A flatten that fails is logged as an error telling you to close by hand; it
  never raises, because the process still has to exit and the log is the only
  record.

This closes the KNOWN GAP in `deploy/README-VPS.md` and the 08-26 / 08-27
failure shape (killed mid-session, positions left open, trades unbooked).

## 3. systemd crash-loop guard was silently inactive

`StartLimitIntervalSec` and `StartLimitBurst` were in `[Service]`. systemd
only reads them in `[Unit]`, logs `Unknown key name`, and ignores them — so
the "restart at most 5 times per hour" guard did nothing and a crash-looping
bot would have retried forever. Moved to `[Unit]`.

Also in `orb-bot.service`, now that shutdown is graceful:
`KillSignal=SIGINT → SIGTERM`, `TimeoutStopSec=30 → 120` (the flatten retries
with backoff; if the timeout expires systemd SIGKILLs and positions are left
open — the exact thing fix #2 exists to prevent).

## 4. The day reports itself — `deploy/eod-summary.sh` + `orb-summary.timer`

The old 16:15 recap read the laptop's `logs/`. Since the migration that folder
is empty, so a clean session and a session that never ran look identical from
the laptop — the same blindness `invariants.py` v1.15/v1.16 was written to
remove, reintroduced by moving hosts.

New timer at **16:05 ET Mon–Fri** on the VPS pushes the result to ntfy. No
laptop involved. It distinguishes the four outcomes that actually differ:

| Situation | Push | Priority |
|---|---|---|
| Clean session | `ORB <date>: Trades: N \| End equity … \| PnL …` + full EOD summary | default (high if any ERROR lines) |
| No log at all | `NO SESSION` | high |
| No `Day done` | `SESSION DID NOT FINISH` + check for open positions | urgent |
| No `Flatten verified` | `FLATTEN NOT VERIFIED` + check for open positions | urgent |

Dry-run verified against three real logs: 09-18 (clean), 09-11 (never ran),
08-27 (killed mid-session). `ORB_DATE=<date> bash deploy/eod-summary.sh`
replays any past day.

## 5. `sync-logs.ps1` — the trailing-backslash bug, fixed

The script written on 09-18 had `"$Local\logs\"` as its destination. In a
double-quoted PowerShell string a trailing backslash escapes the closing
quote, so scp receives a path ending in `"` and dies with `Invalid argument`
— exactly how the 09-20 manual pull failed, since COMMANDS.md carried the
same trailing backslash. Both fixed; the script now also creates the
destination folders and runs `invariants.py` after the pull.

Neither the sandbox nor the laptop's Linux shell can reach port 22, so
syncing is laptop-side by necessity and manual by design.
