## 1. Why "find the best version" is not on this list

Six sweeps plus one out-of-sample holdout. **No strategy parameter change has
ever survived out-of-sample.** The decisive case:

> Run 5 simmed **+2.61/trade at t = 2.74** — the first significant result in the
> project, monotonic across four levels, mechanism matched the literature to
> within half a point. On the Run 6 holdout it came back **−0.07/trade with both
> levers sign-reversed.** 0 of 6 pre-committed criteria passed.

`sweep-results-log.md` already records why: the four relvol levels were not four
independent tests, they were **nested subsets of the same 43 days.** Selecting
the best ~40% of trades by any criterion correlated with outcome looks monotonic
and mechanistically clean whether or not anything is there.

And the instrument is miscalibrated. Same config, same window:
**sim 175 trades / +122.92 vs LIVE 53 trades / +26.92** — 3.3× the trade count,
~+96 of phantom P&L over two months. No sim figure is a forecast until that
closes.

A seventh search would find a winner. It always does. The base rate in this
project says it would be noise, and running it now — days before real money —
is the worst possible timing.

### 1b. Stop the machine sleeping during market hours

On 09-08 a retry backoff of **4 seconds** took **2h56m** (12:01:01 → 14:57:23).
Also 10:45→10:52 and 15:04→15:08. That is suspend/hibernate, not a network blip.
It cost nothing that day only because the bot was already flat.

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 20
powercfg /query SCHEME_CURRENT SUB_SLEEP
```

With a position open and the machine asleep, the bot is blind for hours. Only
broker-side protection (bracket stop + native trailing stop) survives that —
time-stop, news-exit and intraday rescreen all silently stop existing.

## TRACK 4 — Sweep 7, if it happens at all

Ethan asked for this. It is included on one condition: **the criteria get
written down before the run, not after.** Otherwise it is the Run 5 mistake with
a new random seed.

### Non-negotiable protocol

1. **Split the data first.** Tuning window and holdout window are declared in
   writing, in this file, before any command executes. The holdout is never
   looked at twice.
2. **Declare the grid in advance.** Every combo tested gets listed up front.
   Adding combos after seeing results is how 96-combo grids manufacture winners.
3. **Pre-commit the pass criteria** — effect size, t, max drawdown, and the
   requirement that the sign holds in both halves of the holdout.
4. **One sweep at a time.** Four concurrent runs killed three (rate limit, plus
   they overwrite the same `sweep_results.csv`).
5. **Never a bare `>` redirect** — it hides progress, block-buffers, and leaves
   0 bytes if interrupted. Always `python -u ... | Tee-Object -FilePath`.

```powershell
python -u sweep.py --start <TUNING-START> --end <TUNING-END> --no-shorts --trail 1.25 --arm breakeven --tp off --or-minutes 15 --stops 1.5 | Tee-Object -FilePath sweep7_tuning.txt
```

### What I will not do with the result

I will not describe a sweep-7 winner as validated, and I will not recommend it
for live money on in-sample evidence. If it passes a genuine pre-committed
holdout, that changes — and that would be the first time in this project that
has happened.
