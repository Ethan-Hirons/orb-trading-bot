## 2. Create the server

**`console.hetzner.cloud` → New Project (`orb-bot`) → Add Server.**

| Field | Value |
|---|---|
| Location | **Ashburn, VA (US East)** |
| Image | **Ubuntu 24.04** |
| Type | **Shared vCPU → x86 → CPX11** |
| Networking | Leave **Public IPv4 enabled** (needed for SSH) |
| SSH key | Paste your public key (§2.2) |
| Name | `orb-bot` |

Skip Volumes, Firewalls, Placement groups and Cloud config. **Leave Backups
unchecked** — it adds 20% to the bill and the entire state of this box is a git
repo plus two API keys.

Then **Create & Buy Now**. The server is up in under a minute; copy its public
IPv4 from the console.

### 2.1 Notes on those choices

**Location: Ashburn.** US locations cost ~20% more than the German ones and
include 1 TB of traffic instead of 20 TB — both irrelevant here (this bot moves
a few MB a day). Ashburn is close to Alpaca's infrastructure, so pick it for
latency sanity. Either works; the host timezone is set explicitly in §3
regardless of where the datacenter sits.

**Type: CPX11 at the US locations.** Hetzner's `CX` line (Intel) is **EU-only**
— it does not appear at Ashburn or Hillsboro. The US locations run `CPX` (AMD,
x86) and that is what you want. `CAX` is ARM and EU-only; x86 avoids any chance
of a Python wheel not building.

CPX11 is 2 vCPU / 2 GB / 40 GB — comfortably more than a polling loop needs.
Don't go hunting for something smaller. If Ashburn is out of stock, Hillsboro OR
is the other US location and works identically.

### 2.2 SSH key (in PowerShell on your laptop, before creating the server)

```powershell
ssh-keygen -t ed25519 -C "orb-bot"
# accept the default path, set a passphrase or leave blank
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

Paste that output into the **SSH key** box in the Add Server form.

### 2.3 Connect

```powershell
ssh root@<PUBLIC_IP>
```

**Hetzner's default user is `root`, not `ubuntu`.** This differs from Oracle's
image. Because you are already root, **every `sudo` in §3–§9 below is
unnecessary** — the commands work either way, since `sudo` as root is a no-op,
so you can paste them verbatim and ignore the difference.

**You do not need to open any firewall ports.** The bot makes only outbound
HTTPS calls to Alpaca and ntfy. Port 22 is open by default and Hetzner applies
no cloud firewall unless you create one. If you find yourself editing firewall
rules, you've gone off-track.

## 3. Base setup and timezone

```bash
sudo adduser --system --group --home /opt/orb-bot orb
sudo apt update && sudo apt install -y python3 python3-pip python3-venv git curl
sudo timedatectl set-timezone America/New_York
timedatectl
```

**Confirm that last command prints `EDT`.** The systemd timers use local time so
DST is handled automatically — this single line is what permanently kills the
CEST bug class that cost you 08-28 through 09-04. If this is wrong, everything
after it is wrong.

## 4. Get the code

```bash
rm -rf /opt/orb-bot
git clone https://github.com/Ethan-Hirons/orb-trading-bot.git /opt/orb-bot
cd /opt/orb-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

**The `rm -rf` is required, not paranoia.** `adduser --home /opt/orb-bot` in §3
already created that directory (with skel files in it), and `git clone` refuses
to clone into a non-empty existing directory — it fails with "destination path
already exists and is not an empty directory." Removing it does not remove the
`orb` user; the clone recreates the directory and §5 re-assigns ownership.

Your remote was current at `13491e42` as of 09-14. If you've committed anything
since, push it first — `git clone` pulls committed code only, so uncommitted
working-tree edits will not travel.

## 5. The three gotchas — do these before touching systemd

```bash
sudo chmod +x /opt/orb-bot/deploy/*.sh
sudo sed -i 's|\bpython3\b|/opt/orb-bot/.venv/bin/python|g' /opt/orb-bot/deploy/start.sh
tail -3 /opt/orb-bot/deploy/start.sh
sudo chown -R orb:orb /opt/orb-bot
```

**Gotcha 1 — the executable bit.** `.git/config` in this repo has
`filemode = false` because it was authored on Windows, so the exec bit isn't
tracked. `orb-bot.service` has `ExecStart=/opt/orb-bot/deploy/start.sh`, and a
non-executable `start.sh` fails with a cryptic **`203/EXEC`**.

**Gotcha 2 — the venv path.** `start.sh` calls bare `python3` on two lines
(`python3 arm.py`, `exec python3 -u run.py`). With a venv, those hit system
Python, which has no `alpaca-py`. The `tail -3` above must show your venv path
on **both** lines.

**Gotcha 3 — ownership last.** Run `chown` *after* the edits, or the `orb` user
ends up unable to read its own tree.

## 7. Phone alerts

Install the **ntfy** app, subscribe to a long random topic, then:

```bash
echo 'NTFY_TOPIC=orb-bot-<long-random-string>' | sudo -u orb tee /opt/orb-bot/deploy/notify.env
sudo -u orb /opt/orb-bot/deploy/notify.sh "test" "hello from the VPS"
```

**Watch your phone. Do not trust the exit code.** `notify.sh` exits 0 with only
a stderr warning when `NTFY_TOPIC` is unset — so a silent "success" here means
your alerting is dead, which is exactly the failure mode you're trying to fix.
Anyone who guesses the topic can read it, so make it random.

## 8. Install the systemd units

```bash
cd /opt/orb-bot/deploy
sudo cp orb-bot.service orb-bot.timer orb-healthcheck.service \
        orb-healthcheck.timer 'orb-alert@.service' /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now orb-bot.timer orb-healthcheck.timer
systemctl list-timers 'orb-*'
```

Expected: `orb-bot.timer` next fires **tomorrow 09:25 EDT**, healthcheck at
**09:45**. The healthcheck is the piece that covers what `invariants.py` is
structurally blind to — a day that never started.

`Persistent=false` is deliberate: a missed window stays missed rather than
firing the bot at some random hour after a reboot.

## 12. Daily operation

| you want to | do this |
|---|---|
| skip tomorrow | `touch /opt/orb-bot/state/DISARMED` |
| resume | `rm /opt/orb-bot/state/DISARMED` |
| stop a session in progress | `sudo systemctl stop orb-bot` — **does NOT flatten** |
| today's log | `tail -f /opt/orb-bot/logs/orb_$(date +%F).log` |
| health | `python3 /opt/orb-bot/invariants.py` |

### The arming policy is INVERTED — know this

`deploy/start.sh` arms and trades **every market weekday unless
`state/DISARMED` exists**. That is the reverse of your laptop setup, and it is
deliberate: "forgot to arm" cost six consecutive sessions, and on an always-on
host nobody needs to opt in each morning.

For paper, this is what you want — the missing sample is the whole problem.
**Revisit before real money.** With live capital, opt-in is the safer default;
deleting the `DISARMED` check from `start.sh` restores manual arming.

### There is no graceful shutdown

`run.py` catches SIGINT, logs "Bot interrupted by user", and exits — **it does
not close positions**. The unit sends SIGINT rather than SIGTERM so the kill at
least appears in the log, but `systemctl stop` mid-session leaves exactly the
08-26/08-27 mess: open positions, no `Day done`, nothing written to
`trade_history.csv`.

**Until a signal handler calling `_flatten_all_verified` exists, close positions
by hand in the Alpaca dashboard after any mid-session stop.**

## 13. Loose ends this creates

- **The 16:15 recap task reads `logs/` on your laptop.** Once the bot is on the
  VPS those logs live on the box, so the recap will come up empty. Don't let a
  blank recap fool you into thinking the bot didn't run. Fix options: run the
  recap on the VPS, `rsync` logs down nightly, or point the task at the box over
  SSH. Worth doing in the first week.
- **Keep an eye on the Hetzner invoice** for the first month or two so the
  recurring cost stays visible and deliberate. ~€54/year is a real expense for a
  system with no demonstrated edge — worth paying to collect the sample, worth
  cancelling the day you decide the strategy is dead.
- **Incremental trade booking** still doesn't exist — `trade_history.csv` is
  written only at day end, so an interrupted session loses its trades until
  `backfill.py` runs.

## 14. What this does and does not fix

**Fixes:** sessions that never start, mid-day kills, laptop sleep, the CEST/
timezone bug class, no alert when a day is missed, and the unprotected EOD
flatten (the AHCO overnight carry, −37.37 at ~3.6× intended risk).

**Does not fix:** anything about whether the strategy has an edge. After this
the bot will reliably execute a strategy whose expectancy is still **−0.91 per
trade over 88 trades, profit factor 0.871, net −80.11**. That is the point. A
reliable process is what makes the sample worth collecting — and the sample is
what's missing, not another parameter sweep.
