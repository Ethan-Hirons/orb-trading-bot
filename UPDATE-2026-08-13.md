# v1.12 — 2026-08-13: Invariant checks, profit breaker off, opening relative volume

**Status: live path changed in exactly one way (profit breaker). Everything
else is measure-only or offline. Tests 29/29.**

Context: five consecutive red days (Aug 4–12, −152.42) prompted a full review
of all 55 completed trades, the logs, and the ORB literature. Findings are in
REVIEW-2026-08-13.md. Short version: Aug 4–6 (−130.56, 86% of the streak) was
the broken trail already diagnosed in v1.11; Aug 11–12 were two ordinary
one-unit stop-outs (−10.34, −11.52). The system is net +5.06 over 55 trades,
profit factor 1.012 — no demonstrated edge yet, in either direction.

## 1. `invariants.py` — assert what should be impossible

The trailing stop was broken for four trading days before anyone noticed,
because every report answered "what happened today?" and none asked "did
anything happen that CANNOT happen if the bot works?". This is that check.

Read-only, no broker calls, no state writes:

```
python invariants.py              # today
python invariants.py 2026-08-04   # one session
python invariants.py --all --quiet  # regression sweep, only non-PASS
```

Checks: session completed (`Day done`), flatten verified, no overnight carry,
**trail armed when a peak ran past the arming threshold**, trail handoff held,
stops held vs the intended SL parsed from the `ENTER` line, excursion tracking
sane, entries reconcile with `trade_history.csv`, no illiquid name traded, no
silent order-replace failures, no `[ERROR]` lines. Exit code 1 on any FAIL.
Also lists weekdays with **no log at all** — two of the Aug 3–7 validation week
were lost that way (Aug 7, Aug 10) with nothing flagging it.

### What it found immediately, retroactively

- **Aug 3 — the trail never armed on the best day of the trial.** SNXX peaked
  **+11.53%**, SOXL +6.39%, INTC +2.39%, zero `TRAIL ACTIVATED`. The +127.55
  day was three unprotected positions that happened to end well.
- **Aug 4** — CWVX +3.88% and INTC +3.19%, no arm (the known v1.11 case), plus
  a stop breach (CWVX −1.88% vs −1.50%) and `INTC still open` at flatten.
- **Aug 5** — `Failed to close overnight AHCO`, then −5.39% vs a −1.50% stop.
- **NEW, and still unfixed: excursion tracking is systematically understated.**
  Every stopped-out trade shows a MAE milder than the realized loss —
  Aug 12 SNXX MAE −0.94% but closed −1.65%; Aug 11 ACHR −1.19% vs −1.48%;
  Aug 6 INSM −1.23% vs −1.84%; Jul 31 NBIZ −1.07% vs −3.05%. MFE is understated
  too (Aug 3 SNXX peak recorded +11.53%, closed +12.17%).

  This matters beyond bookkeeping: `runner._check_trailing` arms the trail off
  `self._excursion`, so the 30-second poll that is missing these moves is the
  same input that decides whether the trail engages. **v1.11 fixed the ratchet
  but the arming trigger still depends on a lagging sampler.** A name that
  spikes and retraces inside one poll interval can still fail to arm. Worth
  fixing before the trail is trusted — likely by deriving the peak from minute
  bar highs rather than polled last-trade prices.

## 2. Daily profit breaker OFF (`risk.daily_profit_target_pct: 0`)

The only live behavior change. It fired exactly once — 2026-08-03 at +6.14% —
and ended the best day of the trial with the trail (nominally) still running on
three winners. Capping the right tail has no risk justification: the −5% loss
breaker and the EOD flatten bound the downside, and the ORB literature's best
variant is no fixed target plus a close exit.

`risk.py` now treats `<= 0` as disabled; previously a 0 would have fired the
instant the day ticked green. Covered by `test_profit_breaker_disabled_by_zero`.

**Trade-off accepted:** a day can now round-trip from +6% to the −5% breaker.

Per-trade TP was already effectively off (`tp_min/max_pct: 25.0` is an
unreachable bracket ceiling) — no change needed there.

## 3. Opening relative volume — measured, not yet gated

Zarattini, Barbon & Aziz (2024) tested ORB across 7,000 US stocks 2016–2023.
Unfiltered it returned 29% over eight years, Sharpe 0.48, **hit ratio 41.4%**.
Restricted to the day's most unusually active names: 1,637%, Sharpe 2.81, hit
ratio 48.4%. Their gradient by opening relative volume: <100% → −0.02R per
trade, >100% → +0.08R, >3000% → +0.38R.

**This bot's hit ratio is 41.8% — the unfiltered number.** And the metric it
called `rel_volume` was not the paper's:

```python
rel_volume = (actives.get(sym, 0.0) / max_vol) if max_vol else 0.0   # screener.py:171
```

That divides by the *largest* volume among today's actives — a cross-sectional
rank, closer to a market-cap proxy, capped at 1.0 — and it was **0.0 for 45% of
trades** (25/56) while carrying `weight_volume: 0.5` in the ranking. Trades
where it was 0 net −83.82; trades where it was non-zero net +36.94.

Added `Broker.get_avg_opening_volume()` (own opening-window volume over the last
N completed sessions) and a gate in `_scan_for_entries`. Because it is a ratio
of the same feed against itself, the IEX tape-fraction problem that forced the
v1.11.1 liquidity-floor scaling does not apply.

- `strategy.min_opening_rel_volume: 0.0` — **OFF**, measure-and-log only.
- `strategy.rel_volume_lookback_days: 14`
- Every entry logs a `RELVOL` line and writes `rel_volume_open` to
  `trade_features.csv`, so the data to choose a threshold accumulates from the
  next session onward.
- Unknown history never blocks an entry. Skipping every unmeasurable name would
  gut the universe the way the v1.11.1 floor did on 08-11 (44/46 rejected, one
  target all day).
- **Baselines are pre-warmed off the critical path** (`_prefetch_rel_volume`,
  called after the pre-market scan and after each intraday re-screen). The
  first cut measured lazily at breakout time, which put a ~27-day minute-bar
  fetch — the heaviest call the bot makes — between "breakout confirmed" and
  "submit order". The SDK runs with no read timeout (2026-08-12 logged
  `get_news failed ... Read timed out. (read timeout=None)`), so a stall there
  could have cost a fill outright. The entry path is now pure arithmetic on a
  cached number; a cache miss reads as "unknown" and never blocks.
- Watch the `RELVOL baselines: N/M symbol(s) measurable` line on the first live
  run — `get_avg_opening_volume` has never executed against the real API.

## 4. New sweep dimensions (offline only)

`sweep.py` gained three axes. None of these touch the live bot.

```bash
# 1. Relative volume — highest expected value.
python sweep.py --start 2026-06-01 --end 2026-08-12 --no-shorts \
    --stops 1.5 --bias 0.5 --trail 1.25 --arm breakeven --tp off \
    --relvol off,1.0,1.5,2.0,3.0

# 2. Opening range length — paper found 5 min >> 15 min.
python sweep.py --start 2026-06-01 --end 2026-08-12 --no-shorts \
    --stops 1.5 --bias 0.5 --trail 1.25 --arm breakeven --tp off \
    --or-minutes 5,15,30

# 3. Volatility-scaled stop vs the flat 1.5% — an axis never swept before.
python sweep.py --start 2026-06-01 --end 2026-08-12 --no-shorts \
    --stops 1.5 --bias 0.5 --trail 1.25 --arm breakeven --tp off \
    --atr-stop 0.5,0.75,1.0,1.5

# 4. Entry window (>60 min after the open is -101.10 over 10 live trades).
#    No new flag needed — entry_window_minutes in config.yaml, 180 today.
```

Caveat on #1: the sim's `rel_volume` is a **daily** proxy (previous-day volume
/ 20-day average, from `day_candidates`), while the live filter measures the
opening window. Correlated, not identical — a sweep result is evidence the
*concept* works, not a calibrated threshold. Set `min_opening_rel_volume` from
live `rel_volume_open` data once there is enough of it.

## 5. Not done, deliberately

- **No parameter changes.** stop 1.5, trail 1.25, OR 15 min, entry window 180
  min, shorts off all unchanged. The v1.11 trail has still never been observed
  working (zero `TRAIL ACTIVATED` lines in any log, ever — Aug 11 ACHR peaked
  +0.75% and Aug 12 SNXX never went green, so neither could arm it). Changing
  parameters on top of an unvalidated fix destroys attribution.
- **No second strategy / second bot.** Uncorrelated strategies are the real
  answer to a lumpy equity curve, but they only help if each has an edge.
  Splitting 55 trades into ~27 each validates neither.
- **No LLM in the trading loop.** Latency, non-determinism, and it would remove
  the sweep — the one tool that has been settling arguments in this project.
