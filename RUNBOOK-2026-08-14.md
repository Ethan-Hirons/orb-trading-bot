## Run 1 — entry window (the biggest effect in your live data)

```powershell
python sweep.py --start 2026-06-08 --end 2026-08-08 --entry-window 30,60,90,180 --stops 1.5 --bias 0.5 --trail 1.25 --arm breakeven --tp off --no-shorts > sweep_entrywindow.txt
```

**What would confirm the hypothesis:** expectancy rising monotonically as the
window tightens, on a trade count that doesn't collapse. **What would kill it:**
180 wins, or the ordering is noisy. If it dies here, drop it — the live result
was 12 trades and I found it after testing eight splits.

## Run 2 — opening-range length (the paper's largest lever)

```powershell
python sweep.py --start 2026-06-08 --end 2026-08-08 --or-minutes 5,10,15,30 --stops 1.5 --bias 0.5 --trail 1.25,off --arm breakeven --tp off --no-shorts > sweep_orminutes.txt
```

Paper (with its RelVol filter): 5m = 1,637% / Sharpe 2.81; 15m = 272% / 1.43;
30m = 21% / 0.21. If 5-minute doesn't beat 15 here, that's a meaningful
disagreement with the literature and worth understanding before proceeding.

## Run 3 — direction rule

```powershell
python sweep.py --start 2026-06-08 --end 2026-08-08 --first-candle-dir off,on --or-minutes 5,15 --stops 1.5 --bias 0.5,off --trail 1.25 --arm breakeven --tp off --no-shorts > sweep_dirrule.txt
```

`on` = the paper's rule (OR candle body picks the side, doji = no trade).
`off` = live behaviour (breakout side, filtered by news sentiment). Your news
bias has no support in the ORB literature; this is the first test of whether it
earns its place.

## Run 4 — relative volume (concept only)

```powershell
python sweep.py --start 2026-06-08 --end 2026-08-08 --relvol off,1.0,1.5,2.0 --or-minutes 5 --stops 1.5 --bias 0.5 --trail off --tp off --no-shorts > sweep_relvol.txt
```

⚠️ The sim's `rel_volume` is a **daily** proxy (prev-day volume / 20-day
average), not the paper's opening-window ratio. Directional evidence that the
concept works — **not** a calibrated threshold, and not a substitute for fixing
the data feed.

## What changed — v1.13

### Live behaviour (takes effect at the next session; the bot is armed)

- **`config.yaml`: `entry_window_minutes` 180 → 60.** No more late entries.
  Rationale and the post-hoc caveat are in the config comment. This is a
  restriction, so being wrong costs missed trades rather than new risk — that
  asymmetry is why it ships ahead of the sweep while the 5-minute range and the
  direction rule do not.
- **`orb_bot/screener.py`: sticky illiquid set.** A name flagged illiquid in any
  scan today stays out for the rest of the day, logged as
  `ILLIQUID (sticky) skipped ...`. Resets on a new session date. This is the
  NEBX fix, and it makes the bot obey the rule `invariants.py` already enforces.

### Checker

- **`invariants.py`: the stop-breach tolerance was wrong.** It used a flat 1.15x
  and ignored the bot's own `stop_limit_offset_pct`. With stop 1.5% and a 0.5%
  limit band, a fill down to −2.0% is the design working; the threshold sat at
  −1.725%. **ONDS on 08-13 was reported as a FAIL and was not one** — it filled
  at −1.74%, inside the configured band. The budget is now derived from config
  (`stop_budget_pct`), so the check tests the bot against its own contract.
  Verified it still catches the real breach: TRAX 07-10, −3.88% vs a −3.85%
  budget, still FAIL.

### Analysis tooling (no live effect)

- `backtest.py` — `simulate_symbol_day()` gains `first_candle_dir` and
  `entry_window_override`, both defaulting to current behaviour.
- `sweep.py` — `--entry-window`, `--first-candle-dir`, plus `ENTWIN`/`DIR`
  output columns.
- `tests/test_sim_dimensions.py` (10 checks), `tests/test_sticky_illiquid.py`
  (5 checks). All 29 pre-existing tests still pass.

### Still not changed

`opening_range_minutes` (15), `min_opening_rel_volume` (0.0, measure-only), the
news-bias direction rule, `trail_pct` (1.25). Those are strategy changes, not
safety fixes, and they wait on Runs 1–5.
